# Plans

A plan for a substantial change goes here while the work is in progress. Plans are temporary: when a plan is fully implemented, delete it.

So nothing points at a plan. Code, comments, docs and tests don't reference anything in `plans/`. What a plan decided that still matters goes into the code's own comments or into `docs/`, written as how things are, not as the plan or the change that got there.

A plan for a change that touches personal data (a new field about a
person, a new source, a new processor, a new use) says what it does to
`docs/data-protection.md`, to the privacy policy and to erasure before
anything is built (`docs/code-structure.md`).
